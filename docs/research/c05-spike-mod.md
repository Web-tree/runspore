# C05: what a mod does where the docs are silent

Measured on 2026-10-11 with Claude Code 2.1.296 on macOS, terminal surface, in a session driven through a herdr pane. Ticket: [C05 — A spike mod: measure what the docs leave open](https://github.com/Web-tree/runspore/issues/10). The spike mod is on the never-merged branch [`prototype/c05-spike-mod`](https://github.com/Web-tree/runspore/tree/prototype/c05-spike-mod/prototype/c05-spike-mod). Each hook wrote one JSON file per event, and every claim below cites what those files or the screen showed. The API shapes come from the declaration file Claude Code 2.1.296 wrote beside the mod (`.claude-plugin/types/claude-code/index.d.ts`), which the docs say to trust over any page. Start from [claude-code-mods.md](claude-code-mods.md) for what the docs do say.

## Summary

1. **The entry menu is a pane with a `Select`, not `$.ui.ask`.** `$.ui.ask` takes at most 4 options (it rejects 6 with "takes at most 4 options") and adds "Type something" and "Chat about this". A pane opened from the command showed all 8 entries of a sample menu and returned the chosen one to `onSelect`.
2. **The menu hands off to a skill with `$.command.run`, not `$.prompt.submit`.** `$.prompt.submit` refuses text that starts with `/` ("would run a command as the user; run one with `$.command.run`"). `$.command.run({ command: '<plugin>:<skill>', args })`, called from a timer, ran the plugin's skill as if typed, with its arguments.
3. **A process the mod starts dies with the session; a detached one does not.** On SIGHUP, Claude Code sent SIGTERM to a `$.process.spawn` child. A grandchild started with `nohup … &` through `$.process.run` was reparented to PID 1 and kept running.
4. **Claude Code does not check a mod tool's input against its `inputSchema`.** A value outside the enum reached the `tool.call` hook unchanged, and input that is not valid JSON arrived as `{ __unparsedToolInput: { raw, len } }`. The mod has to check the input itself.
5. **A turn cut off by a kill gets no `turn.complete`.** Escape ends the turn with `turn.complete` (`reason: "aborted"`) and no `Stop`. SIGHUP mid-turn fires only `classic.SessionEnd` and `session.end` (`reason: "other"`). Resuming shows the cut-off prompt in the transcript with no answer.
6. **`$.agent.spawn` is refused in auto mode.** In auto mode it returned `{ deny }` ("the server-side auto mode classifier gave no verdict for Agent"), interactively and in `-p`. In manual (default) mode it returned `{ model, agentId }`, and the subagent's answer came in `turn.complete` with that `agentId`.

## Not measured

- SIGKILL of the session. No hook can run, so this needed no test.
- Whether a `$.process.run` child that is still running is killed at session end. A worker would not run through `$.process.run`: it blocks the hook for up to 10 minutes.
- Opening a pane without a person's action (from `session.start` or a timer). The docs say it waits for a 144-column terminal. The menu opens on `/spore`, which counts as an action.
- `asUser: true` on `$.prompt.submit`. The menu has no use for it, since it hands off with `$.command.run`.
- The installed (marketplace) plugin as opposed to `--plugin-dir`. The command name comes from `$.command.register`, which both share.

## What this settles for other tickets

- **C08 (entry menu).** The widget is a pane with a `Select`. `$.ui.ask` is limited to 4 options and refuses in `-p`. The `session.start` notice line fits the budget with a wide margin.
- **C09 (authoring).** "Write a new workflow" and "change a workflow" hand off with `$.command.run({ command: 'ml-workflow:author', args })` from a timer. The skill's name shows as `/ml-workflow:author`.
- **C10 (plugin home).** The mod's command is `/spore`, with no `/ml-workflow:spore` form. The mod must call the helper by `$.plugin.root + "/bin/claude-spore"`, because `bin/` is not on `$.process.run`'s path. Neither `CLAUDE_PLUGIN_ROOT` nor the path gives it to the mod.
- **C06 (who owns the loop).** A worker the mod starts with `$.process.spawn` dies with the session, so it can't own the loop past the session. A worker detached with `nohup … &` survives, but then nothing supervises it. Hooks can't learn about the kill of a turn (no `turn.complete`), so after a crash the run's state must come from `spore`, not from mod memory.
- **C12 (output schemas).** A reporting tool registered by a mod would not get schema checks from Claude Code. That supports C12's choice of `spore` checking every result, plus a report command for interactive steps.
- **C07 / C13 (Claude steps).** An interactive step's first visit uses `--session-id`, and later visits must use `--resume`, as C13 says. herdr drops the agent name when the process dies, which an interactive step's probe can read as *dead*.
- **Agent steps never use `$.agent.spawn`** (C07 runs them in sessions the integration starts). Its refusal in auto mode is one more reason not to.
