workflow.dotDOT dialect, strict subset
  • graph: dialect="runspore/0.1", required, checked first; start="<node>"
  • node: kind = activity (default) | await-signal | complete | fail
  • edge: on="<outcome>"; absent = ok; one outcome per edge; on="failed" is the failure route
  • label, shape, … Graphviz render attributes: kept, no meaning
  • error with a line number: subgraphs, ports, HTML labels, strict, undirected graphs, unknown attributes
settings.jsonJSON, the package's shape minus topology
  • format (agrees with dialect), limits, actions.<id>
  • nodes.<id>: action, input, output, error, signal, instructions: "instructions/review.md"
  • only the files it names enter the artifact; a stray file is ignored
  • build errors name both files: a settings node the DOT lacks, an activity with no settings entry, an outcome with no edge
separate map kind=workflow, a whole workflow as one step
main surface

Writes the whole folder. Topology, kind and on= in workflow.dot; one action per activity, mappings and limits in settings.json; prose only for a step a person performs.

A custom step is an activity bound to a command: any executable. The four kind values are fixed by the kernel.

main surface

Ships the binding next to the program: actions.<id> with "kind": "command", argv, outcomes, exitOutcomes, effect, retry. The node stays a plain activity.

main surface

The worker starts your program from argv, no shell: input JSON on stdin, RUNSPORE_* in env. Stdout is the output (text, json or none).

Exit 0 = ok; exitOutcomes maps other codes; any other code is a retryable failure. Pass RUNSPORE_EFFECT_KEY on, so a retry is safe.

Worked example · deploy/

Max's folder layout (Q11). Node names, commands and digests are examples, not decisions.

deploy/workflow.dot author 

digraph "deploy" {
  dialect = "runspore/0.1"          // required, checked first
  start   = "build"

  build    [kind="activity"]
  review   [kind="await-signal", shape=diamond]  // shape: render only
  release                                // no kind: activity
  done     [kind="complete"]
  rejected [kind="fail"]
  broken   [kind="fail"]

  build   -> review                      // no on= means "ok"
  build   -> broken   [on="red"]
  review  -> release  [on="approved", label="approved"]
  review  -> rejected [on="rejected"]
  release -> done
  release -> broken   [on="failed"]   // the failure route
}

deploy/settings.json author node 

{
  "format": "runspore.workflow/0.1",
  "limits": { "maxVisitsPerNode": 3 },
  "actions": {
    "build": { "kind": "command", "effect": "idempotent",
               "argv": ["make", "release"], "timeoutMs": "600000",
               "outcomes": ["ok", "red"], "exitOutcomes": { "1": "red" } },
    "ship":  { "kind": "command", "effect": "unsafe",
               "argv": ["./ship.sh"], "env": { "STAGE": "prod" },
               "output": "json" }
  },
  "nodes": {
    "build":    { "action": "build" },
    "review":   { "signal": "review",
                  "instructions": "instructions/review.md" },
    "release":  { "action": "ship",
                  "input": { "version": { "$get": ["input", "version"] } } },
    "done":     { "output": { "$get": ["nodes", "release", "output"] } },
    "rejected": { "error": { "code": "review.rejected", "message": "rejected in review" } },
    "broken":   { "error": { "code": "deploy.broken", "message": "build or release failed" } }
  }
}

# Review

Read the release notes for the version in the run's input.
Approve or reject:

ship.sh, the program behind release node

#!/bin/sh
# started by the worker from argv; no shell in between
version=$(jq -r .version)                 # stdin: {"version": "1.4.0"}
./push "$version" --request-id "$RUNSPORE_EFFECT_KEY" || exit 1
echo "{\"shipped\": \"$version\"}"         # output: "json"
# exit 1 is not in exitOutcomes: a retryable failure,
# then on="failed" routes to broken

ship.sh and push live on the worker, not in the artifact.
